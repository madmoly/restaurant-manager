### 1.1 users.hireDate 데이터 점검 (자율 READ-ONLY)
```sql
SELECT COUNT(*) AS notnull_count FROM users WHERE hireDate IS NOT NULL;
SELECT id, name, hireDate FROM users WHERE hireDate IS NOT NULL LIMIT 20;
```
- 결과가 0건이면 그대로 컬럼 DROP 진행
- 결과가 있으면 데이터를 `restaurant_users.hireDate`로 마이그레이션할지 사용자에 보고:

  - 이미 `restaurant_users.hireDate`에 값이 있으면 users 값을 무시하고 DROP

## 3. 정지 조건 (CLAUDE.md §3 외 추가)

본 작업 특화 정지 조건:

### 3.1 마이그레이션 DELETE 5건 실행 직전 (Phase A 단계 [2]) — 최우선
```sql
DELETE FROM employment_electronic_contracts;
DELETE FROM employee_contracts;
DELETE FROM employee_wage_history;
DELETE FROM leave_transactions;
DELETE FROM employee_leaves;
```
이 5건은 **테스트 단계 1회 한정**. 운영 진입(인건비 실 지급 시작) 후에는 절대 재실행 금지.

승인 절차:
1. 마이그레이션 SQL 전체를 5항 보고 형식으로 사용자에 제시
2. 본 시점에 prod DB의 row 수 SELECT로 확인 후 함께 보고:
   ```sql
   SELECT COUNT(*) FROM employment_electronic_contracts;
   SELECT COUNT(*) FROM employee_contracts;
   SELECT COUNT(*) FROM employee_wage_history;
   SELECT COUNT(*) FROM leave_transactions;
   SELECT COUNT(*) FROM employee_leaves;
   ```
3. 사용자 명시 승인 ("DELETE 진행" 또는 동등 표현) 후 실행
4. 실행 후 row 수 0 확인 보고

### 3.2 users.hireDate DROP 직전 (Phase A 단계 [2])
- 사용자 확인 §1.1 SELECT 결과 보고
