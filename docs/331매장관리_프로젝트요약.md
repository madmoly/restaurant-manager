## 1. 프로젝트 개요

331매장관리는 다점포 외식업 운영을 위한 **웹 기반 통합 관리 시스템**이다.

매출 기록, 매입 관리, 인건비 정산, 근무 스케줄, 일일 운영, 전자 근로계약서 등 식당 운영에 필요한 전 범위를 커버한다. PWA(모바일 웹앱)로 구현되어 스마트폰에서 바로 설치·사용 가능하며, OCR 기반 매입전표 자동인식, 실시간 알림, 역할별 권한 분리 등 실용적 기능을 포함한다.

**핵심 특징:**

- 대표(admin)가 여러 매장을 사업그룹 단위로 관리
- 점장/매니져/직원 3단계 매장 역할 + 시스템 역할 분리
- 매입전표 OCR: 사진 촬영 → AI 자동 인식 → 거래처별 학습
- 전자 근로계약서: 토큰 기반 서명 + 스냅샷 보관
- Railway 자동 배포: main push 한 번으로 빌드→배포 완료

## 3. 핵심 기능

### 3.1 매출 관리

- **일별 매출 입력**: 매출유형별 분류 (카드/현금/배달 등) + 특수항목 기록
- **일마감**: 하루 운영 마감 확정 + 특수항목 기록
- **월정산**: 매출·매입·고정비·인건비 집계, 확정 전에도 Excel/PDF 내보내기 가능
- **즉시 지출**: 아코디언에 개별 항목 세부내역 표시

### 3.2 매입 관리 (OCR)

- 매입전표 사진 촬영 → Claude Vision OCR 자동 인식
- 거래처별 OCR 프로파일 자동 생성 (문서 유형, 컬럼 순서, 빈출 품목)
- 사용자 수정 데이터 축적 → 이동평균 단가 학습 → 점진적 정확도 향상
- 서버 검증: 수량/단가 불일치, 이상치 경고, 합계 크로스체크
- 서버 AI 자동 회전 (`detectAndFixOrientation`)
- 노란색 uncertain 항목 표시로 사용자 확인 유도

### 3.3 인사·스케줄

- **직원 라이프사이클**: 빠른입사(quickAdd) → 운영 → 퇴직(resign) → 재입사(reinstate)
- **근무 스케줄**: 오픈/풀/마감 프리셋, 평일/주말 분리, 다중 선택 일괄 배정
- **휴무 관리**: 연차/대체휴무 잔여 계산 + 신청/승인 흐름 (dayoff/half_morning/half_evening)
- **전자 근로계약서**: 토큰 기반 서명 + 스냅샷 12필드 보관, superseded 상태 관리
- **인건비 정산**: 주휴수당·시간별 자동 계산, noWeeklyHolidayPay 별도 조회

### 3.4 운영

- **일일운영일지**: 직원별 매일 운영 사항 기록 (직원도 입력 가능)
- **체크리스트**: 매장별 점검항목 템플릿 + 일일 이행 로그 (유효기간·요구사항 유형 지정)
- **운영 캘린더**: 매장 휴무일·주간 휴무 통합 뷰
- **업무정보 게시판**: 사진 첨부 가능
- **레시피 관리**: 전체 열람, 편집은 manager 이상

### 3.5 관리자 전용

- **사업 대시보드** (`/business`): 매출 추이·목표 대비 달성률·월별 정산 요약
- **사업그룹** (`/groups`): 대표(admin)별 매장 묶음 관리, Tutorial 데이터 격리
- **고정비·거래처·품목 마스터 데이터 관리**
- **시스템 관리** (`/system`): 에러 로그, API 사용량, 시스템 설정 (master 전용)

## 4. 권한 모델

시스템 역할(`users.role`)과 매장 역할(`restaurant_users.role`)을 분리하여 다점포 운영에 적합한 권한 구조를 구현한다.

### 4.1 역할 계층

```
master(개발자, Lv4) > admin(대표, Lv3) > owner(점장) / supervisor(매니져) > staff(직원, Lv1)
```

| 역할 | 식별자 | 설명 |
|---|---|---|
| 개발자 | `master` (시스템) | 시스템 전체 접근 |
| 대표 | `admin` (시스템) | 사업 운영 전체, 소속 매장 관리 |
| 점장 | `owner` (매장) | 매장 전권 — 재무+인사+운영 |
| 매니져 | `supervisor` (매장) | 운영 실행권, 인사 일부 제한 |
| 직원 | `staff` (매장) | 실행만 |

### 4.2 effectiveRole 계산 규칙

1. `users.role`이 master/admin → 그대로 사용 (전역 우선)
2. 아니면 `restaurant_users.role` 확인:
   - owner 또는 supervisor → effectiveRole = `manager`
   - staff 또는 null → effectiveRole = `staff`

### 4.3 점장 vs 매니져 차이 (3건만)

| 기능 | 점장(owner) | 매니져(supervisor) |
|---|---|---|
| 근로계약서 생성/발송 | O | X |
| 인건비 정산 조회 | O | X |
| 소속회사 변경 | O | X |

### 4.4 tRPC 프로시저 6단계

| 프로시저 | 접근 범위 |
|---|---|
| `publicProcedure` | 비로그인 접근 가능 |
| `protectedProcedure` | 로그인 필요 |
| `managerProcedure` | 점장+매니져 공통 |
| `ownerProcedure` | 점장 전용 (인건비, 계약서, 소속회사) |
| `adminProcedure` | 대표+개발자 |
| `masterProcedure` | 개발자 전용 |

매장 소속 자원 접근 시 `verifyStoreAccess` 미들웨어 필수 적용.

## 8. OCR 매입 자동입력 (Phase 1~3 완료)

### 작동 흐름

```
사진 촬영 → 클라이언트 이미지 전처리(2560px/0.92) → 서버 AI 자동 회전
→ Claude Vision OCR (프롬프트: 회전 대응, 양식 4유형, 수량/단가 휴리스틱)
→ 서버 검증 (수량↔단가 뒤바뀜, 이상치 경고, 합계 크로스체크)
→ 거래처별 OCR 프로파일 동적 프롬프트 주입 (품목/단가 힌트)
→ UI에서 uncertain 항목 노란색 표시 → 사용자 확인/수정 → 학습 데이터 축적
```

### 관련 파일

| 파일 | 역할 |
|---|---|
| `server/ocr.ts` | 엔드포인트 + 프롬프트 + 검증 + buildProfileHint |
| `client/src/lib/imageResize.ts` | 클라이언트 이미지 전처리 (OCR_HIGH: 2560px/0.92) |
| `client/src/pages/DailyOpsPage.tsx` | OCR UI |
| `scripts/ocr-test.ts` | OCR 정확도 테스트 |
| `docs/ocr-improvement-plan.md` | 전체 기획서 |

## 12. 새 기능 추가 패턴

1. **스키마**: `drizzle/schema.ts`에 테이블/컬럼 추가
2. **자동 마이그레이션**: `server/index.ts` 시작 시 idempotent ALTER TABLE 추가
3. **라우터**: `server/routers/`에 tRPC 라우터 생성 → `server/routers/index.ts`에 등록
4. **페이지**: `client/src/pages/`에 컴포넌트 생성 → `App.tsx` 라우트 + `AppLayout.tsx` 네비 추가
5. **커밋**: 한글 메시지, 임시 파일에 본문 작성 후 `git commit --file=<path>` 사용
6. **배포**: main 직접 push → Railway 자동 배포

## 13. 작업 규칙 요약

### Single Source of Truth

- **데이터** = Railway DB 단일. 로컬 백업/덤프 커밋 금지
- **작업관리** = GitHub Issues 단일. 로컬 todo.md 금지
- **코드** = origin/main 단일. 로컬 경로 산재 금지
- **패키지매니저** = pnpm 고정. npm/yarn 사용 금지

### 배포 전 의무 보고 5항

| # | 항목 |
|---|---|
| 1 | 변경 파일 목록 (`git diff --stat`) |
| 2 | 변경 의도 (왜 고쳤는가, 1~3줄) |
| 3 | 영향 범위 (DB / tRPC / UI / 권한 모델) |
| 4 | 리스크 (예상 장애 지점, 롤백 방법) |
| 5 | 빌드 결과 (`pnpm run build` 통과 여부) |
